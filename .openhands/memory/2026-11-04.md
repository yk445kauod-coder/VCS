## Hard-won facts (worth keeping)

**Node 24 + `--test test/` fails.** `node --import tsx --test test/` throws
`ERR_UNSUPPORTED_DIR_IMPORT` on ESM. Must use a glob: `node --import tsx --test 'test/**/*.test.ts'`.

**Arabic regexes silently never match.** JS `\b` is ASCII-only, so `/\b(نعم)\b/`
never matches beside Arabic script — no error, just no match. Arabic alternatives
must live in a boundary-free group: `/(نعم|تمام)/u`. This bug was introduced once,
"fixed", and the fix itself silently failed (the python patch didn't match because a
prior edit had changed the line). Verify patches actually landed — assert on the
replacement.

**The storage LIMIT invariant.** In the SQL adapters, `LIMIT` may only be pushed into
the query when *every* `where` key was pushed down; otherwise rows truncate before the
residual JS filter runs and a single-row lookup returns nothing. Guarded by
`hasResidual` in sqlite/postgres/supabase and covered by `test/storage.test.ts`.

**Upsell engine reads the products it is handed.** `findOpportunities({cartProducts})`
does not re-fetch them, so tests must re-read from the catalogue after attaching
upsell rules, otherwise rules look empty.

**Hash-embedding retrieval floor.** A cosine floor of 0.05 on hash embeddings admits
near-noise and pollutes answers with unrelated policies. 0.18 is the working value.

**`node:sqlite` is built in on Node 22+** — the default adapter needs zero native deps.

**Serving port.** The app runs on :8787; the exposed host maps it to :12000.

## Audit pass (2026-11-04, later)

Ran a security audit of the request surface. Four real defects, all fixed and
covered by `test/security.test.ts` (46 tests total now):

1. **SSRF in website ingestion** — `crawlWebsite` (src/ai/brain.ts) fetched any
   tenant-supplied URL. Verified by ingesting a localhost endpoint and reading its
   body back out of the knowledge base. Fix: `src/core/net.ts` —
   `assertPublicHttpUrl` (DNS-resolves, rejects loopback/private/link-local/CGNAT/
   multicast/metadata) and `fetchPublicHttp` (re-validates every redirect hop).
2. **IPv4-mapped IPv6 bypass** — caught by my own test, not by review. The URL
   parser canonicalises `::ffff:127.0.0.1` to `::ffff:7f00:1`, so a dotted-decimal
   regex misses it. Now expands addresses to hextets and judges by value
   (IPv4-mapped, IPv4-compatible, NAT64). Lesson: test a guard against the
   *canonicalised* form the parser produces, not the form a human writes.
3. **Admin token accepted from `?token=`** — global, so it leaked into logs and
   history. Now header-only except `/api/events` (EventSource cannot set headers).
   Dashboard also `history.replaceState`s the token out of the URL.
4. **No rate limit on public agent endpoints** — `/api/webchat/message` runs the
   agent, so unbounded inference spend was possible. `src/core/rate-limit.ts`.

Also: `/api/webchat/history` was not tenant-scoped.

### Gotchas worth remembering
- **`pkill -f "tsx src/server/index.ts"` then restart, or the dashboard serves a
  stale hashed asset and renders blank.** The JS bundle 404s against a
  hash-mismatched index.html. Symptom is a blank page with a ~660b asset response;
  the fix is a restart, not a rebuild.
- Demo DB is `data/duty.sqlite`, gitignored. `rm -f data/duty.sqlite* && npm run
  seed` resets to a clean demo. There is **no tenant DELETE route**, so a test
  tenant can only be removed by deleting the DB file — do that rather than leaving
  "VictimCorp" in a demo.
- Screenshot tooling: `pip install Pillow` works. Quantise UI screenshots to 256
  colours (`Image.quantize`) — ~half the bytes, no visible loss on flat UI.
  Compose composites on a transparent RGBA layer then `getbbox()`+crop, or dead
  background space survives into the final image.
- Committed cruft from the rebuild: 13 `audit*.ts`/`probe.ts`/`repro_storage.ts`
  scripts and a `__pycache__`. Check `git ls-files` for scratch files after a
  large rebuild.


## Later session — production deployment

Found and fixed two real defects by exercising the system against live
infrastructure rather than mocks:

1. **`count()` capped at 1000 rows in every adapter.** Only surfaced against a real
   Neon DB with 1100 documents behind it — sqlite tests never had enough rows. Every
   analytics number was built on it, so revenue would have silently frozen at 1000.
2. **LLM errors propagated out of `handleInbound`.** Pointing a real Gemini key at
   the system and sending 6 orders in a minute (free tier = 5/min) produced: no
   reply, no order, 5xx. Now degrades to the deterministic brain and still sells.

Both are covered by regression tests (50 total, up from 46).

Also worth remembering: the `Order` type's line-item field is **`lines`**, not
`items` — I got it wrong in a test first.

Deployed: Cloudflare Worker edge (`deploy/cloudflare/`) + Neon Postgres, app running
in this sandbox. Verified the whole path in a browser: the `/demo` storefront drives
a real sale through the edge into Neon.
